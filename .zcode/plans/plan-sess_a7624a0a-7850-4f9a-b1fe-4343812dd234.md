# ZenSidus 数据层重构：relay server + client 迁移实施计划

## Context

App.md 设计稿已定稿：数据获取全面迁移到自建 relay 服务器（JP VPS），客户端全程只有一条 TCP（postcard 帧），彻底移除 HTTP/WS 直连；Alpaca/Finviz/DeepSeek 凭据下沉服务端，客户端只持 relay token。七问报告（`D:\Development\Project\ZenSidus\AnySDK\integration_report.md`）是服务器侧 anysdk 编码依据。用户已确认：① crate 命名 `client`/`server`/`relay-protocol`；② TLS 由服务器 Nginx + CF 证书终结（server 明文 TCP，客户端 TLS 可选 + 证书固定）；③ 干净切换，不保留直连降级路径。

现 workspace：`crates/app`（~12.5k 行，bin ZenSidus / lib app_lib）+ `crates/gateway_sdk`（~382 行）。零现有 TCP/postcard 代码。`Server/`、`Gateway/` 是独立仓库（CF Worker），与本次无关。

## 阶段 P0a：工作空间重命名 + 新 crate 骨架

1. `crates/app` → `crates/client`：package `app`→`client`，lib target `app_lib`→`client_lib`（main.rs 导入、build.rs、`cargo test -p` 命令同步改）；bin 名仍 `ZenSidus`。
2. 新建 `crates/relay-protocol`（package `relay-protocol`）、`crates/server`（package `relay-server`，bin `relay-server`，暂为空壳 main）。
3. 根 Cargo.toml：members 增至 4 个；workspace.dependencies 增加 serde/serde_json 已有，新增 `postcard = "1"`、`bitflags`（serde feature）、`tokio`（full）、`futures`、`tracing` 等。
4. 验证：`cargo build --workspace` 全绿后 commit（boundary commit P0a）。

## 阶段 P0b：relay-protocol crate（App.md §2.2 + D1/D2）

文件：`crates/relay-protocol/src/lib.rs`（Frame + codec）+ `rpc.rs`（payload/DTO）+ `screener.rs`（ScreenerParameter DTO）。依赖仅 serde/postcard/bitflags。

- 帧格式：`[u32 LE 长度][postcard Frame]`；提供 `encode_frame` + 增量式 `FrameDecoder`（缓冲半包，client/server 共用）。
- `Frame`（字段名/类型严格按 App.md 草图；推送载荷用结构体以便 Snapshot DTO 复用，字段不变）：
  - `Hello { token: String, app_version: String }` / `Welcome { server_time_ms: i64 }`
  - `Ping` / `Pong`（客户端 10s 间隔）
  - `Subscribe { id: u32, symbols: Vec<String>, channels: Channels }` / `Unsubscribe { 同 }` / `Subscribed { id: u32 }`（D1：symbols 即 `Vec<String>`）
  - `Quote(QuoteData)` / `Trade(TradeData)` / `Bar(BarData)` / `News(NewsData)`——字段照草图（Quote 8 字段无 conditions/tape；Trade 带 conditions 无 tape；Bar 带 `kind: BarKind{Minute,Updated,Daily}`；时间统一 `time_ms: i64`）
  - `RpcRequest { id: u32, payload: RpcRequestPayload }` / `RpcResponse { id: u32, result: Result<RpcResponsePayload, String> }`
  - **`RestProgress { req_id: u32, fetched: u64 }`**（D2，报告新增；配合 bars_all_with_progress 进度）
- `Channels` bitflags：`TRADES | QUOTES | BARS | DAILY | NEWS`（草图 4 项 + **DAILY 拆出**——Watchlist 的 Change 只需日线 open，现 hub 订 trades+dailyBars；若 BARS 混含分钟 bar 会白耗带宽。这是对草图的必要补充，协议侧写明语义：BARS=分钟/更新 bar，DAILY=日线）
- `RpcRequestPayload`：`News{symbols,limit}` / `Bars{symbols,timeframe,start,end,limit}` / `Snapshot{symbols}` / `ScreenerExport{parameter:ScreenerParameter}` / `MarketScreenerExport{parameter}` / `Search{keyword,lang}` / `Translate{from,to,text}` / `EconomicCalendar{date}` / `EarningsCalendar{date}` / `IpoCalendar`
- `RpcResponsePayload`（全 owned DTO）：`News(Vec<NewsItem>)` / `Bars(BTreeMap<String, Vec<Bar>>)`（Bar 含 vwap/trade_count）/ `Snapshot(Vec<SnapshotItem{symbol, latest_trade/latest_quote/minute_bar/daily_bar/prev_daily_bar: Option<…>}>)` / `ScreenerExport{headers, rows}` / `MarketScreenerExport{headers, rows}` / `Search(Vec<SearchItem{name,symbol}>)` / `Translate(String)` / `EconomicCalendar(Vec<EconomicItem{event,time_ms,impact,r#for,actual,expected,prior}>)` / `EarningsCalendar(Vec<EarningsItem>)` / `IpoCalendar(Vec<IpoItem>)`。EarningsItem/IpoItem 字段从 `gateway_sdk/src/finviz.rs`、`ipo.rs` 现抄。
- `ScreenerParameter` DTO：镜像 anysdk `finviz_sdk::screener::Parameter` 字段（实现时从源码现抄），server/client 两端各写一个转换函数。
- 测试：每个 Frame 变体 postcard 往返单测 + FrameDecoder 半包/粘包用例。
- commit P0b。

## 阶段 P1：relay-server crate（App.md §2.4 + 集成报告）

依赖：tokio、anysdk(git, full)、relay-protocol、reqwest(rustls)、toml、tracing、chrono+chrono-tz、futures、scraper（IPO HTML 解析）。

模块：`main.rs`（config 加载 + listener）、`config.rs`（`server.toml`：listen/token/alpaca{key,secret,feed}/finviz{token}/deepseek{key}；`server.toml.example` 入库、真文件 gitignore）、`executor.rs`（`HttpExecutor<reqwest::Client>`，照抄 AnySDK `crates/test/src/main.rs:27` 模式）、`upstream.rs`（StockStream + NewsStream 各一条，StreamStatus 日志）、`hub.rs`（per-client 意愿表 → 上游并集引用计数 → anysdk `StockSubscription` diff）、`session.rs`（每连接 actor：Hello token 校验失败即断、60s 无帧超时、收发路由、每客户端出站 mpsc）、`rpc.rs`（全部 RPC handler）。

关键映射（以集成报告签名为准）：
- 上行映射：Channels→`StockSubscription{trades/quotes/bars/updated_bars/daily_bars}`；TRADES→trades（自动带 corrections/cancel_errors）；BARS→bars+updated_bars；DAILY→daily_bars；NEWS→服务端 NewsStream `subscribe_all`（启动即连，单条上游）
- 下行映射：`StockMessage::Quote→Frame::Quote`（丢 conditions/tape）、`Trade→Frame::Trade`（保 conditions）、`MinuteBar/DailyBar/UpdatedBar→Frame::Bar{kind}`、`NewsMessage→Frame::News`
- RPC：`bars` 用 `bars_all_with_progress(params, |fetched| 发 RestProgress{req_id, fetched})`，终值走 RpcResponse；`screener/market_screener` 走 finviz_sdk（DTO↔Parameter 转换）；`economic/earnings` = finviz_sdk 日历 + **gateway_sdk::finviz 行加工逻辑整体移植**（economic_rows/earnings_rows/build_timestamp/周窗口参数及其单测随迁）；`search`=futunn HTTP（照 Gateway TS `src/api/search.ts` 逻辑）；`translate`=DeepSeek 代理；`ipo`=iposcoop HTML 抓取（linkedom→scraper）
- 心跳：Pong 回 Ping；订阅协商回 `Subscribed{id}`；客户端断开撤销其意愿并重算上游
- README：nginx `stream` 块 TLS 终结示例（用户选定方案）+ systemd unit 样例；慢客户端 coalescing 留二期（一期每客户端 unbounded 出站）
- 测试：hub 并集/引用计数、上行下行映射、economic/earnings 行加工（迁移原测试）、DTO 转换
- commit P1。

## 阶段 P2：client 迁移（App.md §2.3，工作量最大）

**新 `utils/relay.rs` RelayClient**（替代 executor 三客户端 + 两条 WS 的唯一落点）：
- 连接状态机：Connecting/Connected/Reconnecting(退避 1s→60s)/Failed/Closed；断线自动重连 + **订阅重放**（内部保存期望订阅集，镜像 anysdk supervisor 语义）；TLS 可选（`tokio-rustls` + ring provider；`settings.relay.tls=true` 时：有 `tls_cert` 路径则 SPKI/DER 固定校验（CF Origin 证书不受公共信任），否则走系统 webpki 根）
- `subscribe/unsubscribe(id, symbols, channels)`、`rpc(payload) -> oneshot<Result<RpcResponsePayload,String>>`（HashMap<u32, oneshot> 路由）、`stock_messages() -> broadcast<StockMessage>`、`news() -> broadcast<NewsData>`、`status() -> broadcast<RelayStatus>`、`server_time_ms()`（Welcome + Ping RTT 校正）
- Frame→anysdk 类型映射（**stream_dispatch 级联零改动**的关键）：Quote→`StockMessage::Quote(QuoteMessage{conditions:vec![],tape:None,…})`、Trade→Trade{tape:None}、Bar{kind}→Minute/Daily/UpdatedBar、time_ms→`DateTime<Utc>`

**hub 重接**：`utils/state/alpaca_hub.rs` → `relay_hub.rs`（`AlpacaHub`→`RelayHub`，`AlpacaStatus`→`RelayStatus` 映射保持状态灯语义）；`SymbolWish{symbols,trades,quotes}` 聚合/引用计数/watchdog 保留，wire 命令换成 relay.subscribe/unsubscribe（trades 意愿→TRADES|DAILY，quotes 意愿→QUOTES）；staleness watchdog 保留（数据源换 TCP 帧）。

**面板/窗口逐个迁移**（对照 App.md §1.1-1.14 映射表）：
- watchlist/quote/trades/market_screener/etf_linkcalc：消费 broadcast 的逻辑不动（hub 换底即可）
- stock news：`alpaca_client.news` → `relay.rpc(News)`；凭据守卫改连接守卫
- market news：**NewsStream 删除**；NEWS 通道常驻订阅 + news broadcast 供帧；HTTP 回填→RPC（保留 merge 语义）
- stock/market screener：finviz_client → RPC；settings `Parameter`→DTO 转换；finviz token 守卫删除（token 下沉服务端）
- economic/earnings/ipo 日历：RPC；行类型 gateway_sdk `EconomicRow/EarningsRow`→协议 DTO（datatable delegate 同步改，时间列由 time_ms 本地格式化）
- small clock：`gateway_client.timestamp()` → relay 对时；经济提醒走 RPC EconomicCalendar
- search/translate 对话框：gateway_client → RPC Search/Translate（保留 300ms 防抖/代数防乱序/window_handle 强制重绘——见 zensidus-app 技能陷阱）
- ETF linkcalc：snapshot 锚点 → RPC Snapshot（当日 daily_bar open + 日期门控保留）

**基础设施**：`executor.rs` 删除；AppState 去掉三客户端/http_client，hub 内建 RelayClient；`settings.rs`：新增 `[relay] addr/tls/tls_cert` + keyring `relay-token`（沿用 sanitize/keyring 模式），删 alpaca key/secret、finviz api_key、feed、ws_proxy 字段（serde 默认容忍旧文件）；settings 窗口 alpaca 页 → relay 页；status_bar/MessageLog/i18n 文案跟进（en-us/zh-cn 同步加删 key）。

验证：`cargo check/clippy/test -p client`（settings 往返测试更新）；本机起 server + app 连本地 relay 手测清单（各面板数据、状态灯、杀 server 重连、lag 行）。commit P2。
